# Глоссарий

**Токен** — минимальная единица текста, с которой способны работать большие языковые модели (LLM). Любой текст перед обработкой LLM предварительно преобразуется в последовательность токенов, которые затем переводятся в числовые представления, удобные для анализа и обработки моделью.
Они могут быть размером от одного символа до целого слова — в зависимости от языка и контекста. Пробелы, знаки препинания и части слов тоже учитываются при подсчёте токенов.

**Аугментация** – это построение дополнительных данных из исходных при решении задач машинного обучения.

**EDA (Exploratory Data Analysis)** — это первичный исследовательский анализ данных: просмотр распределений, статистик, примеров и аномалий, чтобы понять датасет перед моделированием.

**EDA (Easy Data Augmentation)** — это набор простых правил аугментации текста (замена слов синонимами, вставка, перестановка и удаление слов), чтобы получить дополнительные обучающие примеры.

**Эмбеддинг** — это числовой вектор фиксированной длины, который кодирует объект (например, слово, предложение или письмо) так, чтобы близкие по смыслу объекты имели близкие векторы и их можно было использовать в ML-моделях.

**Стемминг** — это грубое “обрезание” слова до основы (например, “доставки”, “доставка”, “доставить” → что-то вроде “достав”), часто с ошибками, но быстро.

**Лемматизация** — приведение слова к нормальной форме (лемме) с учётом морфологии (например, “доставки”, “доставкой” → “доставка”).

**Абляция (ablation study)** — это эксперимент, где вы по одному убираете или добавляете компонент метода (например, лемматизацию, char n‑grams, аугментацию) и сравниваете метрики, чтобы понять вклад каждого компонента.

# Постановка задачи

Прикладная задача — **многоклассовая классификация рабочих email-писем**, с учётом сильного дисбаланса.

В рамках темы ВКР не “просто классификатор”, а через исследование представлений текста:

1) Построить векторные представления текста (эмбеддинги/композитные представления) для писем.
2) Применить их для многоклассовой классификации и сравнить качество.
3) Оценить влияние предобработки и аугментации (особенно для редких классов) на метрики (macro‑F1 и т.д.).
4) Выявить, какие представления/композиции дают лучший результат при ограничениях: малый датасет, длинные тексты, дисбаланс.

То есть “классификация писем” — это целевая прикладная задача, а “композитные векторные представления” — основной исследовательский фокус и то, что нужно сравнить в работе.

# baseline

нормализация текста -> TF‑IDF для токенизации и векторного представления -> линейный классификатор(Linear SVM, Logistic Regression, Naive_bayes Bias)

Подробнее:

## Нормализация
ё→е, приведение пробелов, верхний регистр, унификация кавычек/тире

## Аугментация

TF-IDF нужно будет построить дважды, до аугментации и после.

### Дополнительные обучающие примеры не изменяя текст, а **беря части письма**:
- первые N предложений (часто там суть),
- N самых информативных предложений (по TF‑IDF),
- случайное окно из N предложений.

### Лёгкий шум
- случайно удалить 3–8% слов, **но не трогать** “не/ни”, плейсхолдеры `[NAME]`

## Токенизация
TF‑IDF с двумя типами токенов и объединить их признаки в один общий вектор:
1) **word n‑grams (1–2)**: токены = слова и пары слов. Плейсхолдеры сделать токенами.
   Пример: `оплата`, `по_счету`, `прошу_выслать`
2) **char n‑grams (3–5)**: токены = последовательности символов длины 3–5  
   Пример: `опл`, `плат`, `счет`

# С использованием LLM

Использовать Transformer. Например, RuBERT, но из-за длины писем использовать чанки, классифицировать куски и агрегировать.

## Аугментация

### Семантические (наиболее эффективные, но требуют моделей)
1. **Back-translation** (обратный перевод): RU→EN→RU (или RU→DE→RU).
2. **Парафразирование генеративной моделью** (LLM / seq2seq):  
   “Перефразируй, сохрани смысл и класс, не добавляй новых фактов”.  
   Нужны фильтры и ограничения.
3. **Контекстная замена слов (contextual augmentation)**: замена токенов через masked language model (например, RuBERT MLM).  
   Лучше, чем словарные синонимы, но может менять смысл (особенно для терминов).

### Аугментации в пространстве эмбеддингов (для нейросетей)
1. **Mixup / manifold mixup**: смешивание представлений двух примеров и их меток (обычно soft labels).  
   Хорошо для нейросетевых классификаторов; для линейных моделей на TF‑IDF неприменимо напрямую.
2. **Adversarial training**: небольшие возмущения эмбеддингов (FGM/PGD).  
   Повышает устойчивость, но это уже скорее метод обучения, чем генерация текстов.
3. Замена N случайных слов (не стоп-слов) на их синонимы из тезауруса (WordNet) или заранее обученных эмбеддингов (ближайший сосед в пространстве векторов).

Фильтры качества:
1) Семантическая близость: cosine similarity по sentence-эмбеддингам (например, RuSBERT) > 0.80 (порог подбирается).
2) Длина: 0.7–1.3 от исходной (чтобы не были слишком короткие/длинные).
3) Self-check классификатором: baseline TF‑IDF модель должна предсказать **тот же класс** с вероятностью/маржой выше порога.
4) Дедупликация: убрать почти одинаковые тексты (MinHash/SimHash).

## 2) Как выбирать модель (критерии)
### Критерий A: язык и домен
- Для русских деловых писем лучше начинать с **RuBERT**-семейства (обучены на русском).
- Если письма содержат много англицизмов/артикулов/смешанный язык — можно рассмотреть **multilingual**.

### Критерий B: размер модели vs ваш датасет
1700 писем — небольшой датасет, поэтому:
- **base**-модели (≈110–180M параметров) обычно ок.
- слишком большие модели повышают риск переобучения и требуют больше VRAM.

### Критерий C: длина входа
Стандартный BERT = **512 токенов**. Письма длинные, значит вам нужно:
- либо **chunking** (рекомендую как основной путь),
- либо модель “для длинных текстов” (Longformer/BigBird). Для русского это сложнее и не всегда оправдано.

### Критерий D: лицензия и воспроизводимость
Для ВКР удобно брать модели с понятной лицензией (Apache-2.0/MIT) и хорошей документацией.

## 4) Как использовать готовые модели: 3 рабочих сценария

### Сценарий 1 (самый простой и часто сильный): TF‑IDF + Linear (без GPU)
Это не “готовая нейросеть”, но это baseline, который почти всегда надо иметь. Он обучается быстро на CPU.

### Сценарий 2: “Готовая модель как эмбеддер” + простой классификатор
1) Берёте RuBERT (без fine-tuning).
2) Для каждого письма получаете эмбеддинг:
    - либо `[CLS]` по каждому chunk,
    - либо mean pooling по токенам,
    - затем агрегируете по chunks (mean/max).
3) На этих векторах обучаете Logistic Regression/Linear SVM/XGBoost.

Плюсы:
- меньше риск переобучения, чем при полном fine-tuning,
- быстро, удобно для сравнения “векторных представлений” в вашей теме.

Минусы:
- может уступать fine-tuning.

### Сценарий 3: Fine-tuning RuBERT под вашу классификацию (GPU)
1) Делаете chunking длинных писем.
2) Обучаете классификатор на chunks (каждому chunk присваиваете метку письма).
3) На инференсе агрегируете вероятности по chunks (например, среднее или max).

Трюки для малого датасета и дисбаланса:
- `class_weight` или **focal loss** / weighted cross-entropy
- early stopping
- заморозка части слоёв (freeze embeddings + первые N слоёв)
- небольшие learning rate (2e-5…5e-5), 3–10 эпох
- stratified split, macro‑F1 как основная метрика

---

## 5) Как именно делать chunking для писем (практический стандарт)
- max_length: 256–384 токенов (чтобы влезало в VRAM и было больше батч)
- stride/overlap: 32–64 токена (чтобы не терять границы смыслов)
- агрегация:
    - mean по вероятностям классов (стабильно),
    - или max (если класс определяется “одним абзацем”),
    - можно сравнить.

Дополнительно: перед chunking лучше удалить подписи/цитаты, иначе chunks будут “про мусор”.
